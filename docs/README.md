# File to RC — Documentation

`file-to-rc` turns any file into **Windows resource script (`.rc`) source**,
an `RCDATA` resource whose bytes are written inline, so the file is compiled
into the `.exe` / `.dll` by the resource compiler and read at run time with
`FindResource` / `LoadResource`. It is both:

- **a command line tool**, `file-to-rc`, run from build scripts;
- **a C++ library**, namespace `XYO::FileToRC`, with the conversion as a
  function (`fileToRC`), and the tool itself as a class that can be
  embedded in another program (fabricare does, as `fileToRC(...)`).

One output form:

```
file-to-rc --name=logoPng --file-in=logo.png --file-out=Logo.Source.rc
```

```rc
logoPng RCDATA {
	0x5089,0x474E,0x0A0D,0x0A1A,...,
	...
}
```

## Why it exists

A Windows program can carry data as resources: an icon, a default
configuration, a script, a certificate. The resource compiler can already
take a file by name (`logo RCDATA "logo.png"`), but then the `.rc` depends
on a second file that must be found on the resource compiler's path when
the `.rc` is compiled. `file-to-rc` writes the bytes into the `.rc` itself:

| Problem | What `file-to-rc` does |
|---------|------------------------|
| The resource script must be self-contained, no extra file at `rc` time | writes the data inline as 16 bit words, `NAME RCDATA { 0xHHHH,... }`, 16 per line |
| Binary content can not be written as text | every two bytes become one `0xHHHH` word; `rc` stores words little endian, so the bytes come back exactly |
| `rc.exe` breaks tokens on very long lines | 16 words per line, any input size compiles exactly |
| Regenerating on every build forces a resource recompile | `--touch=file` regenerates only when the input is newer than the output, then touches the `.rc` that includes it |
| Several resources in one generated file | `--append` adds one more `RCDATA` line to an existing output |
| Long build command lines | `@file` response files |

For files of several megabytes, where the `.rc` does not need to be
self-contained, `NAME RCDATA "file"` compiles faster (the generated `.rc`
is 3.5 times the size of the input). See
[Output format](output-format.md#line-length).

## Concepts at a glance

| Need | Command line | Library |
|------|--------------|---------|
| Embed a file as an `RCDATA` resource | `file-to-rc --name=logoPng --file-in=logo.png --file-out=Logo.Source.rc` | `XYO::FileToRC::fileToRC("logoPng", in, out, false)` |
| Several resources in one file | second and later calls with `--append` | `append = true` |
| Regenerate only when changed | `--touch=Application.rc` | `Shell::compareLastWriteTime` yourself |
| Run the tool from your own program | | `XYO::FileToRC::Application::Application` (`file-to-rc.application.static`) |
| Read it at run time | `FindResourceA(module, "LOGOPNG", MAKEINTRESOURCEA(10))` + `LoadResource` + `LockResource` + `SizeofResource` | |
